# Этапы исследования

Статус: предлагаемый roadmap, не утверждённый план реализации. Порядок нужен, чтобы различать вклад представления кода, retrieval и агентной модели.

## 0. Репозиторий и проверяемая постановка

- [x] Зафиксировать цель: переносимый локальный исследователь 1С.
- [x] Разделить encoder, индекс, MCP и агентное поведение.
- [x] Собрать первоисточники и открытые вопросы.
- [ ] Утвердить техническую спецификацию первого retrieval-эксперимента.

## 1. Корпус и baseline без обучения

- Синтетические Configurator/EDT-примеры с явно заданными релевантными местами.
- Разрешённая реальная выгрузка, хранящаяся локально вне Git.
- Проверка полноты парсинга и координат перед оценкой поиска.
- Лексический поиск; LateOn-Code-edge; при необходимости доменный dense baseline.
- Замеры токенизации русских вопросов и составных идентификаторов BSL.

Критерий перехода: воспроизводимый прогон на фиксированных данных и revisions; известны качество, пропуски, память и стоимость индексации. Численные пороги определяются в спецификации до запуска сравнений.

## 2. Адаптация multi-vector encoder

- Подготовить русские вопросы, релевантные фрагменты и трудные отрицательные примеры.
- Проверить утечки общих процедур между обучением и оценкой.
- Сравнить contrastive fine-tuning и/или distillation с исходным encoder.
- Измерить компромисс качества с размером индекса и задержкой.

Критерий перехода: преимущество на конфигурации вне обучения или обоснованное решение сохранить исходную модель/другой baseline.

## 3. Общий движок и MCP

- Определить минимальные версионируемые схемы инструментов.
- Добавить поиск, чтение и необходимые структурные переходы.
- Проверять соответствие выдачи текущему снимку индекса.
- Обеспечить доступ основной модели напрямую для контрольного сравнения.

Критерий перехода: доказательства разрешаются в реальные исходники; неполнота и устаревший индекс явно видны клиенту.

## 4. Локальный агент без дообучения

- Проверить небольшую общую модель с ограниченным бюджетом поиска.
- Сравнить с прямым использованием того же backend основной моделью.
- Отдельно учитывать ошибки retrieval, выбора инструментов и вывода.

Критерий перехода: выявлены воспроизводимые ошибки поведения, которые имеет смысл исправлять обучением; добавочная задержка и полнота измерены.

## 5. SFT агента и перенос

- Собрать и проверить траектории учителя на реальных ответах инструментов.
- Обучать поиск и доказательное завершение, включая задачи без ответа.
- Проверить на другой конфигурации и на самописном продукте вне train.
- Оценивать релевантные процедуры, доказательства, ложные выводы, API-токены, p50/p95 задержки, fallback и качество решения основной модели.

RL остаётся возможным последующим исследованием после устойчивого SFT baseline и надёжной оценки.

## Воспроизводимость

В каждом прогоне фиксировать корпус/снимок, разбиение данных, model revision, tokenizer, схему инструментов, seed, ограничения контекста, параметры индекса, оборудование и software versions. GPU-обучение и сравнительные прогоны на одной машине выполнять последовательно.

# BSL Scout Agent: предложение архитектуры

Дата: 2026-10-17. Статус: исследовательское предложение для обсуждения; реализация не начата. Документ фиксирует направление, а не утверждает, что компоненты уже существуют или технические решения окончательно выбраны.

## Намерение

Основная модель разрабатывает продукт на 1С и делегирует локальной маленькой модели ограниченные исследования. Исследователь должен ориентироваться в ранее неизвестной выгрузке по инструментам поиска, структуре метаданных и исходникам. Основная область применения — самописный продукт; периодически исследуются типовые конфигурации.

Учебные конфигурации можно расширять постепенно. ERP рассматривается как один из полигонов обучения. Главная проверка — перенос на конфигурации, исключённые из обучения.

Целевая первая машина: Ryzen 5 7600, 32 ГБ RAM, RTX 4070 SUPER 12 ГБ VRAM. Время, память и качество на ней пока не измерены.

## Рекомендуемый подход

Собственный тонкий MCP-интерфейс и общий поисковый движок, переиспользующий подходящие библиотеки. Исследовать multi-vector retrieval на LateOn-Code-edge; отдельно оценивать дообучение encoder и обучение агентного поведения. Не начинать с одновременного обучения обоих компонентов.

Альтернативы:

1. Расширить сам ColGrep поддержкой BSL/EDT. Можно сохранить большую часть его локального поискового стека, но потребуется разобраться в его внутренней модели данных и способе добавления языка.
2. Написать MCP-фасад над существующим 1С-индексатором. Это быстрый способ получить контрольный результат и полезный источник решений по структуре, но не проверяет преимущество собственного multi-vector retrieval.
3. Собственный BSL-слой с заимствованием идей из ColGrep и сообщества. Даёт нужный контракт и возможность независимой оценки компонентов; требует больше работы по парсингу, обновлению индекса и проверке полноты. Это выбранное направление исследования, а не разрешение немедленно писать весь стек.

## Границы компонентов

`Выгрузка → адаптер формата → общее представление → индексы → поисковые операции → локальный агент → досье для основной модели`.

### Адаптеры исходников

Configurator XML/BSL и EDT должны давать единые сущности: проект, конфигурация/расширение, объект метаданных, модуль, процедура/функция, обработчик/подписка, ссылка на источник. Конкретный BSL-парсер ещё нужно выбрать по проверке на синтетических примерах и реальных разрешённых выгрузках.

Регистр имён, русские/английские ключевые слова и контексты клиент/сервер нельзя бездумно стирать. Оригинальные идентификаторы и исходный текст сохраняются. Граф статических вызовов может быть неполным: динамические вызовы и неоднозначные имена нужно отражать в результате.

### Представление для поиска

Основная единица кода — процедура или функция с контекстом: конфигурация, объект, вид модуля, сигнатура и исходные координаты. Для длинных процедур нужны дочерние фрагменты с привязкой к родительской процедуре. Метаданные индексируются отдельными карточками; запросы 1С внутри BSL могут потребовать особого разбиения.

Базовый поиск по точным именам/тексту должен работать независимо от encoder. Multi-vector ветка сравнивает векторы токенов запроса и документа, после чего результаты объединяются с лексической выдачей. Конкретные fusion, индекс и компрессия выбираются по замерам.

### MCP и CLI

ColGrep прежде всего CLI. В нашем проекте CLI и MCP могут вызывать один движок; агентная логика не должна дублироваться между транспортами.

Предлагаемые операции: поиск, чтение исходного фрагмента/процедуры, структура объекта, переходы по вызовам, поиск обработчиков/подписок/вмешательств расширений, завершение исследования. Окончательные имена и JSON-схемы пока не утверждены. Версия интерфейса должна быть записана в обучающих траекториях.

Отдельно различать прямой поиск для основной модели и делегированное исследование маленькой LLM. Это позволит измерить, нужен ли агент для конкретного класса задач.

### Досье исследователя

Каждый вывод опирается на источники: проект, релиз или commit при наличии, снимок индекса, объект, модуль, процедура, путь, строки и фрагмент. Сервис извлекает фрагменты из исходников и проверяет координаты; LLM не должна сочинять текст доказательств.

Также возвращаются проверенные области, исключённые источники, неоднозначные связи, лимит исследования и незакрытые вопросы. Неполный поиск не должен превращаться в утверждение об отсутствии механизма. Основная модель может продолжить поиск напрямую.

## Две задачи обучения

### Encoder: русский вопрос → релевантный код и метаданные

Сначала проверить LateOn-Code-edge без обучения: кириллическую токенизацию, длину представления сложных идентификаторов, полноту top-k и точность ранжирования. Multi-vector matching не отменяет ограничений базового tokenizer и обучения преимущественно на английских запросах.

Затем подготовить пары/тройки: вопрос, релевантные фрагменты, трудные нерелевантные кандидаты. Примеры ошибок: одноимённые обработчики разных объектов, чтение регистра вместо записи, соседний механизм, другой релиз, вмешательство расширения. Контрастивное обучение и дистилляция оценок учителя — кандидаты, которые поддерживает PyLate.

### Агент: задача → выбор действий → доказательства

Обучать выбору операций, уточнению запросов, прослеживанию связей и корректному завершению. Для SFT нужны проверенные траектории с реальными ответами инструментов. До обучения можно использовать общую маленькую модель как контроль.

Изменение схем инструментов или семантики результатов меняет среду агента и требует повторной оценки. ColGrep-Agent связан со своим исходным harness; перенос на новые инструменты не считается автоматически работающим.

## Данные и переносимость

Разделять train/eval по конфигурациям и задачам; учитывать общие библиотеки, типовые копии и близкие процедуры между релизами. Отдельный тест с необычными именами проверяет зависимость от запоминания терминов.

Для обучения использовать только данные, на которые есть соответствующие права. Публичность проекта не означает публичность ERP, коммерческих конфигураций, материалов ИТС или пользовательского продукта. Публикация весов требует отдельной проверки условий обучающих данных и базовой модели.

## Что входит в первый эксперимент

Первый шаг — оценка retrieval без локального агента: синтетический BSL/XML/EDT-корпус и разрешённый локальный корпус, общий формат поисковых единиц, лексический baseline, LateOn-Code-edge, метрики полноты, ранжирования, памяти, размера индекса и задержки.

Далее отдельно добавляются обучение encoder, общий MCP-интерфейс и агент. Выбор языка реализации, парсера и хранения — открытые решения для следующей технической спецификации. Их нужно принимать по прототипу и требованиям, а не угадывать заранее.
